# 图片创建中断后的等待与任务找回

2026-10-29。用户截图显示创建时出现 `Failed to fetch`，本机记录处于未知状态、没有任务凭据，按钮因防止重复计费而锁定。截图不能单独证明服务商拒绝了请求、没有扣费或未完成生成；真实服务商状态需要查询后台记录。

## 修复

- `/media/generate` 上游等待上限从20秒改为90秒，浏览器创建等待从35秒改为110秒；状态查询仍分别为20/35秒，查询与生成分开计时。没有调整用户选择的2K、高思考、联网搜索参数。
- 浏览器网络中断显示中文说明。提交前配置读取失败不会新建本机未知任务；服务器通过 `creation_state` 区分尚未派发的拒绝和已派发但结果不明，前者可以修正后重新提交，后者继续保留防重锁。无自动付费重试。
- 对旧版遗留的 `unknown` 或刷新中断的 `creating` 记录，图片页显示“找回原图片任务”。用户自行从服务商记录中复制 `task_id`；`POST /api/image/recover` 仅使用原服务商和已保存密钥GET查询现有任务，验证编号/状态后签发当前浏览器专属、24小时有效的加密任务凭据，再沿用状态查询和结果保存。
- 任务编号不匹配、查询失败或无权限时保留原本机记录，不创建图片。找回已成功任务后保存原结果；已失败任务显示失败供核查。历史图片、Markdown风格、植物方案和版本保留。
- 继续保留显式“核查服务商记录后清除本机任务”入口；用户应先确认无任务或已核查处理情况，避免重复计费。清除时本机保存失败不会先清空内存记录。
- 服务端记录创建排查编号、参数摘要及失败阶段，不记录API密钥、原始提示词或Markdown内容。查询失败说明会持久保存，刷新后仍可继续查询。
