主导航“方案工作台”后新增独立的 **AI 绿化效果图** 页面，支持选择项目、上传 Markdown 风格文件并带入图片生成；风格按项目在本机保存，刷新可恢复。见 [效果图页面说明](docs/visuals/effect-studio.md)。

## 启动

本地开发（不需要部署平台配置）：

```bash
node scripts/build-worker.mjs --local
node scripts/validate-artifact.mjs --local
node server.mjs --local
```

本地配置在 `.openai/local-build.json`，产物隔离在 `dist/local/`。此文件是项目自有的本地预览配置，不是部署平台的 `hosting.json`，不包含密钥。预览服务仅监听本机，并使用模拟登录身份；不能直接作为生产服务。

以下原有命令面向平台构建，仍需由原部署平台提供有效的 `.openai/hosting.json`；该配置目前未入库。本地构建成功不代表生产部署已验证。

先运行 `node scripts/build-worker.mjs`，再运行 `node server.mjs`，访问 http://127.0.0.1:4173 。当前界面源码在 `web/`，服务端在 `worker/index.js`，无第三方运行依赖。`dist/server/index.js` 为生成的Worker产物；旧的 `dist/` 静态文件仅为历史保留，不再作为编辑入口。

## 支持的操作

- 项目新建、编辑、删除、本机保存。
- 上传道路断面、现场照片、区位资料（图片/PDF，每个文件最多12MB）。
- 案例新增、编辑、删除、搜索、按分带筛选和项目引用。
- 按输入宽度、养护偏好与案例笔记生成分带概念建议。
- 快捷调整、自由文本指令留存、20个版本的查看与恢复。
- Markdown方案、项目JSON、含附件的工作空间备份导出与合并导入。

## 实现边界

此版为浏览器本机工作空间：LocalStorage存记录，IndexedDB存附件，不跨设备同步。规则模式不自动理解上传图片/PDF，不调用大模型；API模式通过服务端调用所选聊天模型，发送案例/规范文字、项目条件和已确认的道路数据，生成植物配置与分段数据，由网页绘制矢量图。规则植物初选来自设计案例的有限品种词表与浙江、北京、广州区域参考模板；未覆盖品种需人工补充。具体品种、尺度与当地适用性仍需专业校核。

## 2026-10-13：植物与海绵功能

- 输出具体主选植物、备选植物、种植位置与种植形式，并记录参考资料来源。区域参考可手动指定，自动匹配只覆盖有限城市。
- 海绵选项分为考虑、不考虑、待定；考虑时可指定侧分带/中分带、设施形式、土壤入渗与溢流排放条件。
- 海绵植物按高区、过渡区、低区形成候选配置，窄带先提示设施可行性。设施深度、容量、控制指标不由规则引擎确定。
- 新字段参与方案更新提醒、版本保存/恢复、项目备份与Markdown导出。旧版方案提示重新生成，保留既有记录。

后续可在服务端接入模型API、资料解析、项目数据库、案例检索与地域植物校核。API密钥应放在服务端，不能嵌入网页。

## 项目案例库

每个案例按完整项目保存，可分别上传平面图、断面图和其他资料。图片在上传时、案例卡片和详情中直接显示；支持图片放大、封面选择、图纸名称与说明。PDF、DWG/DXF及常见文档作为附件保存，单个案例附件最多25MB。

设计内容由用户填写总体说明、行道树、侧分带、中分带和海绵设计。仅项目名称必填，允许先上传资料再补充说明。区域、道路类型、设计阶段、参考部位及各绿带宽度均可记录。已有案例兼容保留，未分类的旧附件归入其他资料。

案例备份包括原附件、封面、图纸名称及全部设计说明，可在案例库中导入。未保存的文件移除与文字修改不会改动原案例。案例用于当前项目选择；具体模型生成与图纸理解仍属于后续接入工作。方案页面和导出不再展示案例借鉴过程说明。

## 2026-10-14：统一植物配置

结果仅保留植物配置栏目，包含种植平面、道路断面、配置文字和统一品种表。两张 SVG 采用同一道路结构，横向按输入宽度绘制；默认道路组成需要用户与上传断面对照确认，可从左到右编辑，支持无中分带、单侧与非对称结构。

优先参考案例按用户选择排序；支持的品种词表用于替换植物清单，案例原文仅存于案例和历史数据中，不在方案页面或Markdown引用。植物配置文字在同一栏目内按行道树、侧分带、中分带分点展示，未启用的部位不显示。曲线、砾石、分段关键词控制海绵图形。任意文本、图纸坐标和数量无法自动解析。典型模块为24m，分段示意采用8m海绵区加4m节点；竖向、植物符号、种植密度与工程量仍需深化。图纸分别下载SVG，配置文字导出Markdown，旧方案和版本保留并提示重新生成。

生成按钮上方新增行道树种植形式：连续绿带 / 单个行道树（独立树池）。该选项影响植物位置、配置文字、平面树池形态及断面标识，参与变更检测和版本恢复。旧项目默认为连续绿带；不设计行道树时隐藏选项。树池示意不代替根系空间、树池长度和设施退让的实际校核。

## 方案调整与项目规范

方案调整默认使用已保存的API模型理解完整意见，支持多品种与上下层搭配，不受原方案生成模式限制；也可明确切回固定规则。未配置模型时先打开设置，失败保留原方案，不会自动重试付费调用。见 [模型调整接入记录](docs/visuals/model-adjustments.md)。

方案下方可输入文字并重新生成。支持按部位修改主选品种、替换、增加、删除植物，修改株距、独立树池/连续绿带、曲线、砾石、分段和海绵设置。已应用指令和暂未识别描述分别显示；未知描述不会声称已执行，植物替换须存在原品种。调整优先于案例配置，保留版本，可恢复。所有新增品种仍需设计师校核当地适用性。

项目规范主导航按国家和地方分类，支持PDF、Word、TXT、Markdown、图片原件，每个文件25MB。TXT/Markdown小文件导入摘录；PDF/Word不自动解析。用户记录编号版本、适用地域和具体条款，在各项目勾选适用规范。支持最小/最大带宽与乔木株距的数值校核，冲突阻止生成或调整，不自动改变道路结构；其他条款显示待人工核对。未选择规范或未录入条款不代表已审查通过。

规范及附件纳入工作空间备份；条款变更触发方案过期提醒。校核记录保存于方案版本及Markdown。法规现行性、适用性和完整性由设计师依据原件确认，系统不预置未经核实的条款，也不输出全部规范达标结论。

## DS-V4-Pro方案生成（2026-10-20）

默认模型 deepseek-v4-pro，默认地址 https://api.lk888.ai/v1/chat/completions ，可在模型设置中更改服务商地址和模型。使用Bearer鉴权、流式 Chat Completions、max_tokens及JSON输出。请求超时180秒含正文读取，不自动重试；错误保留脱敏后的服务商说明。

密钥在网页“模型设置”填写，由运行时secret ROADSCAPE_SESSION_SECRET加密，以身份绑定的Secure/HttpOnly/SameSite=Strict会话保存，保存后有效90天。密钥不写入源码、项目、备份或localStorage。配置绑定服务商与模型，更换服务商地址须提供相应密钥，不转发原地址的密钥。

发送项目条件、已确认道路结构、所选案例及规范文字、当前方案和调整意见；附件原件不发送。服务端校验模型返回的植物、描述和分段，网页保留原道路顺序/宽度绘制SVG平面与断面。历史gpt-image-2图片仍可在历史版本中查看和导出。失败或输入变更时不覆盖原方案。

网站已按用户要求公开，可在其他电脑打开。项目、案例、规范和附件仍是各浏览器本机数据，换电脑需导出完整工作空间备份并导入。API调用需登录，各浏览器单独填写自己的密钥；未登录可使用案例规则模式。

接口和界面使用模拟上游验证；真实服务商连接需用户保存新密钥后测试，不能把模拟测试视为模型账户已通过。
