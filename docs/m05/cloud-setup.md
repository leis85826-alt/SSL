# M05 云端同步：Cloudflare 配置与验收

2026-10-26。代码可在本地模拟环境运行；实际账号资源尚未创建/验证。本指南不代表已经开启云端同步。

## 1. 当前需要准备的资源

继续使用原 `roadscape-model-preview` Worker 和网站，保持原站点域名，以保留浏览器本机数据。

1. Cloudflare → Storage & databases → **D1 SQL Database**，新建独立数据库，建议名 `roadscape-m05`。记录 Database ID。
2. 同区域菜单 → **R2 Object Storage**，创建存储桶，建议名 `roadscape-m05-files`。保持私有，不启用公共 r2.dev 链接或公共自定义域名。R2 可能要求启用账户计费，请依据 Cloudflare 实际页面办理；代码不代办或创建费用资源。
3. Zero Trust → Access → Applications，新建 **Self-hosted** 应用，保护工作台域名下 `/api/v1/*`，策略只允许你的邮箱和需要使用云端项目的成员。可使用 Email One-time PIN 登录。模型及公开工作台路径继续沿用现有设置。
4. 记录团队域名（例如 `your-team.cloudflareaccess.com`，不要包含 https://）和该应用的 **AUD**。Access 域名/AUD 不是 API Token。若控制台不支持直接为当前 workers.dev 域名配置该路径，请先给 Worker 绑定你持有的自定义域名再设置，不要通过关闭 JWT 校验绕过。

需要的配置标识：D1 Database ID、存储桶名称、Access 团队域名及应用 AUD，可选 Account ID。不需要把模型 API 密钥或 Cloudflare API Token 发到聊天。

## 2. 生成绑定配置（不操作云端）

在本机仓库根目录，使用真实标识替换尖括号内容：

```bash
node scripts/configure-m05-cloud.mjs --database-id <D1数据库ID> --bucket <R2存储桶名称> --access-domain <团队名.cloudflareaccess.com> --aud <Access应用AUD>
```

生成 `wrangler.m05-cloud.jsonc`，包含 `M05_DB`、`M05_FILES` 绑定及 Access 设置，默认 **M05_ENABLED=false**。脚本只写配置，不创建资源、部署或执行迁移；已有文件不会覆盖。原 `wrangler.jsonc` 不变，未填写标识时原站继续工作。

如果通过 Dashboard 管理，可在 Worker Settings → Bindings 添加：

| 类型 | 绑定名 | 选择 |
|---|---|---|
| D1 Database | `M05_DB` | 新建的独立数据库 |
| R2 Bucket | `M05_FILES` | 新建的私有桶 |

在运行时变量中设置 `M05_ACCESS_TEAM_DOMAIN`、`M05_ACCESS_AUD`、`M05_REQUIRE_ASSETS=true`，先保留 `M05_ENABLED=false`。现有 `ROADSCAPE_SESSION_SECRET` 留在 Secret 类型，不复制为普通变量。模型密钥保持原有个人加密 Cookie，不存入项目库或附件。

GitHub Builds 的 Wrangler 配置也是配置来源：Dashboard 加绑定后，需要将实际绑定纳入构建使用的配置，避免后续 Git 部署丢失绑定。生成文件被 Git 忽略；管理员可审核后将非敏感标识合入正式 wrangler 配置，再提交代码。不能把带占位 ID 的示例直接部署。

## 3. 迁移及启用顺序

先导出真实本机工作台附件备份与工程数据包，在独立浏览器验证恢复。对已存数据的云库，另做 D1 export 和 R2 清单/对象备份；本项目没有自动恢复/清空生产库脚本。

在新建的专用空数据库或明确授权的副本上依次运行：

- `migrations/m05/0001_s1.sql`
- `migrations/m05/0002_cloud_files.sql`

这两份 SQL 都只新增 M05 表/索引/触发器，不迁移或删除旧工作台数据。可以在 D1 Console 执行文件内容。若使用 CLI，请先确认实际账户和目标库，选择其明确的 `--remote`/`--local` 目标；本轮没有执行远端 SQL。

先用预览应用验证登录、资源绑定和迁移，再将 `M05_ENABLED` 改为字符串 `true`。使用生成配置的构建命令需明确指定 `--config wrangler.m05-cloud.jsonc`；已审核合入正式配置则沿用原构建命令。不要将本地测试的假账号服务或假数据库 ID 带到生产。

## 4. 工作台如何使用

1. 打开项目标题右侧“项目数据与版本”，先建立或导入工程数据。
2. 点击“登录云端”，按 Access 邮箱登录。同一账号在其他设备会得到稳定项目身份；模型浏览器会话不作为项目身份。
3. 点击“上传当前工程与工作台”。只上传当前项目、历史版本引用的案例/规范及它们的附件，以及全部本机工程版本；不会上传其他项目或密钥。
4. 在另一台电脑用同一账号登录，选择“查看我的云端项目”→“下载为本机副本”。会新建项目/工程/附件 ID，已有本机数据保留。
5. 第一台设备基于旧云端版本再次上传时会返回冲突，拒绝覆盖；先下载新副本核对。没有后台静默覆盖、自动冲突合并或自动上传真实历史数据。

上传前校验所有工程历史的附件 SHA256/大小；缺少原件时先拒绝，不静默丢弃。新项目会先出现一个初始化版本，附件及清单保存成功后才产生完整同步版本；中断可在原设备再次点击上传继续，不应将未完成初始化项目当作完整同步结果。

当前同步限制：单附件25MB、单项目最多100个文件/合计100MB、工作台+工程历史清单2MB、列表最多100项目。D1/R2 套餐的请求数、SQL/绑定/Worker限额可能更低，实际容量需上线前验证；本轮不是千株性能或大文件压测验收。超过限制或存储失败保留本机数据，未完成版本不替代成功版本。

远端生成的香蕉效果图保留服务商链接，不主动抓取外部地址；原图请另存后作为项目附件上传，才能按原件存入 R2。文件未做病毒扫描，下载强制 attachment/octet-stream；成员应上传可信资料。

## 5. 安全与一致性边界

- Access JWT 使用固定团队证书端点、RS256 验签、issuer/audience/时间/subject校验，再对 issuer+subject 计算稳定账号ID；伪造邮箱或 oai 身份头无效。JWKS缓存5分钟，轮换后新 kid 最迟在缓存过期后生效。
- 项目接口执行 owner/READER/EDITOR 权限检查。当前 UI 没有成员授权编辑器，普通账号不能通过输入 project_id 读取他人数据。
- R2对象不公开，不接受调用者指定任意 storage_key，不提供从任意 URL 抓取文件的接口。下载先检查项目权限。相同附件 ID 内容不同返回409；相同内容复传可以复用。
- 工程快照只有在附件元数据及对象存在性校验后才保存，版本事务失败不会更新当前指针。
- 上传跨 D1/R2 多步骤，不是分布式原子事务。失败可留下未引用对象/已上传资源；不自动删除，以免并发误删。任何清理都需先检查全部历史版本引用。此同步不是 S6 预览确认/幂等提交引擎。
- 恢复跨浏览器 LocalStorage 与 IndexedDB，同样不是单一事务；若附件/工作台已恢复但工程库写入失败，会明确提示部分完成，不覆盖既有项目，云端原件仍保留。
- 下载为副本会重建本机资源映射及校验和，保持植物坐标与逻辑对象身份；原已过期方案不会因复制被标记为有效。只有源方案本来匹配设计条件时，复制后才重算 ID 变更导致的界面指纹。

## 6. 验收与回滚

先在真实资源上用非敏感小样本验证：同账号两设备、另一账号拒绝、CAD/照片字节与哈希、历史工程版本、断网/重新上传、409冲突、原本机数据和模型功能。通过后再由用户明确选择上传真实项目。

回滚先将 `M05_ENABLED=false`，回退代码到 `3529716`，保留 D1/R2/本机库，不 DROP、不清空桶、不轮换现有模型密钥。云端关闭不会删除任何项目。实际生产备份恢复、R2版本保全及帐号策略尚需管理员核定，不能仅凭本地模拟宣称上线验收通过。

## 本地复现（不接触远端）

验证环境需要 Node 24、Python Playwright 与 Chromium；这些不是网站运行依赖。运行 `node scripts/test-m05-cloud-local.mjs`，使用临时配置、数据库/桶和本地账号stub验证两个浏览器；脚本只运行 `--local`，不修改真实 Cloudflare 账号。单独的 Access JWT 密码学验证在 Node 测试中。不要把测试stub或临时配置用于生产。
