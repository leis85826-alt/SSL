# 工程量估算页面第一版

主导航“工程量估算”。以项目为单位保存quantityEstimate，包含标准段长度、总长度、范围、地区/期次/计价口径、标准段详细清单与上传文件元数据。详细行按部位、工程类型、品种名称、规格、单位、标准量、重复/一次性、增减量、手工单价和来源编辑。

上传Excel/CSV/PDF每份最多20MB，仅留存原文件到IndexedDB并提供下载。UTF-8 CSV支持按模板列名导入最多500项：部位、项目名称、规格、单位、标准段数量；不声称Excel/PDF智能识别、联网信息价查询或智能体匹配已接入。智能匹配按钮禁用且明确待接入。

总量=标准量×总长/标准长，一次性项目系数1。株/套/个向上取整，再加人工增减；其他单位保留两位小数。价格空白为缺价，0为明确零价；金额是已填价项目小计，不冒充完整工程造价。材料价不自动追加施工、运输、养护和税费。修改参数后需重新换算，导出可用Excel打开的CSV，防止公式注入。各部位按清单实际范围计算，不自动乘二。

本机保存；上传文件暂不承诺包含在通用工作空间备份中，原文件请另保留。本次同时修复section-editor的change处理，只处理自身section-*控件，避免清空新页面或其他模块文件输入。

验证：新增3项Node单元测试，合计52项通过；浏览器验证CSV、明细、换算、缺价/手工单价、一次性项、文件保存、导出、刷新、存储失败和移动端无溢出；断面编辑器和独立布局浏览器回归通过；Cloudflare/本地构建和产物校验通过。未使用真实模型、信息价或客户资料。

## 方案模型接入

智能资料助手使用已保存聊天/方案会话，不使用banana图片任务协议、不新增共享密钥。服务端POST /api/model/quantity（extract/match）复用同源、浏览器身份、加密会话、目的地址校验、超时与NDJSON进度。最多16万字/2000段资料，一次提取最多200项，匹配最多80项，不自动重试。

浏览器按需加载本地ExcelJS 4.4.0与PDF.js 4.10.38，读取.xlsx、CSV、文本PDF；保留工作表行号/PDF页码与文本段号。旧.xls需转换，扫描PDF需OCR，超过80页PDF或容量限制需分批。用户可勾选参与分析文件。仅提取文字发送模型，原文件不上传服务商；不联网查价。第三方许可证随组件保留。

模型提取清单和候选单价均须返回来源id及逐字原文；服务端校验引用真实存在且数值可在引用中核实。地区/期次未指定时降为相近候选。模型不负责金额计算。候选需人工确认追加/采用，清单变动后候选失效，异步返回时输入变化不覆盖原数据。采用后保留原文件、位置、原文、模型标识和时间。所有匹配包括exact仍需人工核对数量含义、规格、单位与价格范围；数值在原文出现不等于语义已自动审定。

测试：7项服务端接入/依据校验测试，合计59项Node通过；真实合成Excel及文本PDF在浏览器提取，模拟模型验证确认/取消、原文位置、旧候选拦截，在生产等同CSP下通过。原工程量页面回归、本地与Cloudflare构建通过。未使用真实API账户、收费模型或真实客户资料验证，不声称真实服务商权限及模型效果已验证。
