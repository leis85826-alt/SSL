# M05-02 数据结构与 API 接口规范
版本：V1.0｜2026-10-22｜Roadscape AI Studio
## 1. 基本架构
前端编辑→业务API校验与权限→几何规则引擎→短期预览→用户确认→事务提交→不可变版本→DXF与苗木表读取同一revision。AI只生成结构化意图，不直接操作数据库。建议HTTPS+JSON；数据库与技术栈根据现有工程审计适配。
## 2. 八个核心实体
Project(project_id,name,city,road_type,crs,source_unit,unit_to_meter,current_revision_id,owner_user_id,created_at,updated_at)。
PlantSpecies(species_id,chinese_name,scientific_name,category,evergreen_type,usage_tags,suitable_regions,symbol_id)。
PlantSpecification(specification_id,species_id,trunk_diameter_cm,ground_diameter_cm,height_m,crown_diameter_m,branch_height_m,default_density)。
PlantingArea(area_id,project_id,revision_id,name,area_type,geometry,excluded_geometry,usable_area_m2,source_layer,locked)。
PlantingAlignment(alignment_id,project_id,revision_id,geometry,direction,length_m,geometry_version)。
PlantingRule(rule_id,project_id,revision_id,area_id,alignment_id,rule_type,species_config,parameters,constraints,conflict_strategy,algorithm_version)。
PlantObject(object_id,project_id,revision_id,object_type,species_id,specification_id,area_id,rule_id,group_id,geometry,station_m,quantity_method,density_per_m2,estimated_quantity,lock_mode,logical_key)。
DesignRevision(revision_id,project_id,revision_number,parent_revision_id,status,created_by,created_at,change_summary,algorithm_version,checksum)。
辅助实体：权限、资源文件、PlantGroup、预览、审计日志、导出任务。逻辑对象身份与版本记录身份分开。
## 3. 几何与对象约束
工程空间必须声明坐标参考和单位。实例对象Point，区域对象Polygon/MultiPolygon，线状对象LineString/MultiLineString。禁止把未投影经纬度当米计算。按实例与密度估算须采用不同quantity_method并避免重复统计。历史版本不可修改；新提交产生新版本。
## 4. 规则枚举与字段
EQUAL_SPACING, GROUP_PLANTING, ALTERNATING, HEDGE_ROWS, GROUNDCOVER_AREA, AREA_PARTITION。GROUP_PLANTING参数：group_size、intra_group_spacing_m、group_end_center_gap_m、start_offset_m、end_offset_m、lateral_offset_m、tail_policy。组间距定义为相邻两组端部植株中心距，非组首周期。
## 5. API通用约定
统一路径前缀/api/v1；HTTPS+JSON；统一success/data/request_id或success=false/error(code,message,details)。状态码200/201/202、400、401、403、404、409、422、429、500。所有写操作做用户身份及项目级权限检查，校验JSON Schema与引用一致性。正式提交需Idempotency-Key与base_revision_id。
## 6. 16个主要业务API
POST /projects 创建项目；GET /projects/{id} 查询项目；GET /plant-species 查询植物库；GET /projects/{id}/planting-areas 查询区域；POST 同路径创建区域；POST /projects/{id}/planting-rules 创建规则；PATCH /projects/{id}/planting-rules/{ruleId} 修改规则；POST /projects/{id}/planting/previews 创建预览；GET /projects/{id}/planting/previews/{previewId} 查询预览；POST /projects/{id}/planting/commits 提交；GET /projects/{id}/plant-objects 查询植物；PATCH /projects/{id}/plant-objects/{objectId} 修改单株；POST /projects/{id}/plant-objects/batch-preview 批量预览；POST /projects/{id}/ai/parse-command AI解析；GET /projects/{id}/planting/statistics 苗木统计；POST /projects/{id}/exports/dxf 导出DXF。
另需配套版本历史、CAD数据读取及导出任务状态API。
## 7. 预览示例
```json
{
  "base_revision_id":"44444444-4444-4444-8444-444444444444",
  "rule":{
    "rule_type":"GROUP_PLANTING",
    "target_area_id":"55555555-5555-4555-8555-555555555555",
    "alignment_id":"66666666-6666-4666-8666-666666666666",
    "species_config":{"species_id":"22222222-2222-4222-8222-222222222222"},
    "parameters":{"group_size":5,"intra_group_spacing_m":4,"group_end_center_gap_m":12,"start_offset_m":4,"end_offset_m":4}
  },
  "conflict_strategy":"REPORT"

```
返回preview_id、base_revision_id、algorithm_version、candidate_count、accepted_count、rejected_count、conflicts及changes(added,removed,moved,updated)。预览无数据库正式副作用，设时效和不可篡改摘要。
## 8. 提交接口
POST /projects/{id}/planting/commits，包含preview_id、base_revision_id、confirmation=true与变更摘要。验证身份与项目写权限、预览归属及时效、校验摘要、409并发检查、硬冲突检查，然后事务创建新Revision、保存对象、更新current_revision_id和审计记录。网络重复同幂等键及相同请求体返回首次结果。
## 9. AI接口
POST /projects/{id}/ai/parse-command，输入base_revision_id、selected_object_ids、message；输出intent、target解析及parameters和requires_confirmation。服务端名称解析为真实ID，多义指令先澄清。AI调用工具也遵守业务权限，不执行任意SQL。
## 10. 数量与CAD
GET /projects/{id}/planting/statistics?revision_id=... 返回物种、规格、对象类型、实际株数/种植面积、密度、理论数量、取整规则及版本。POST /projects/{id}/exports/dxf 固定revision_id，按植物对象工程坐标和符号映射生成图元；DXF应可编辑并可追溯对象。DWG不视为原生DXF处理的直接能力。
## 11. 云端与安全
结构化数据和原始CAD/图片等文件分开存储。跨电脑登录读取项目、正式版本、对应资源和规则。并发写入要base_revision_id进行乐观锁；拒绝静默覆盖。限制大文件上传、跨项目对象访问与AI越权修改；记录审计日志。
## 12. 交付规范
